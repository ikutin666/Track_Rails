# ИИ-сервис аналитики для MWS Track Rails

## Краткое описание

Проект представляет собой интеллектуальный сервис аналитики, встроенный в платформу
MWS Track Rails. Он позволяет пользователю формулировать аналитические запросы обычным
человеческим языком и получать готовые таблицы, графики, информационные панели и
текстовые отчёты.

Пользователю не требуется знать структуру базы данных, язык SQL или вручную собирать
данные из нескольких систем. Достаточно написать, например: «Покажи просроченные задачи
за последний квартал по командам и объясни основные причины задержек». Сервис определит
необходимые показатели, применит права доступа, получит данные и сформирует понятный отчёт.

## Ключевые возможности MWS Track Rails

MWS Track Rails — платформа управления разработкой, которая уже предоставляет командам
основные инструменты для организации работы:

- создание проектов по командам, подразделениям и направлениям;
- создание задач, назначение исполнителей и контроль статусов и сроков;
- прикрепление документов, инструкций и других файлов к задачам;
- управление ролями, правами доступа и видимостью задач;
- ведение спринтов и списков задач по методологиям Agile;
- обсуждение работы в комментариях и получение уведомлений об изменениях;
- использование ИИ-агентов владельца продукта, аналитика, разработчика и тестировщика;
- развёртывание в облаке или в инфраструктуре заказчика.

Проектируемый сервис не заменяет эти возможности. Он добавляет аналитический слой,
который использует уже накопленные данные продукта и позволяет обращаться к ним на
естественном языке. В дальнейшем результаты отчётов можно отправлять в комментарии и
уведомления MWS Track Rails, сохраняя работу пользователя внутри привычного интерфейса.

## Проблема

В MWS Track Rails накапливается большой объём информации о задачах, проектах, командах,
исполнителях, сроках и спринтах. Дополнительные сведения могут находиться в системе
управления клиентами, учёте рабочего времени, финансовых и документных системах.

Чтобы получить сводный отчёт, пользователю часто приходится обращаться к аналитику,
выгружать данные, объединять таблицы и вручную строить диаграммы. Такой процесс занимает
время, создаёт очередь запросов к аналитикам и повышает вероятность ошибки. Кроме того,
данные могут устареть ещё до завершения подготовки отчёта.

## Цель проекта

Цель проекта — сделать аналитику MWS Track Rails доступной сотрудникам без специальных
технических знаний и сократить время между возникновением вопроса и получением ответа.

Для достижения цели сервис должен:

- принимать запросы на естественном языке через встроенный чат и программный интерфейс;
- понимать сущности, показатели, периоды, фильтры и требуемый вид результата;
- объединять данные MWS Track Rails и разрешённых внешних источников;
- безопасно формировать и выполнять запросы к данным;
- строить таблицы, графики, информационные панели и текстовые пояснения;
- соблюдать ролевую модель и изоляцию данных разных организаций;
- работать достаточно быстро для интерактивного использования;
- контролировать расходы на использование языковых моделей.

## Основные пользователи

Сервис ориентирован на руководителей проектов и подразделений, владельцев продуктов,
руководителей команд, специалистов по работе с клиентами и аналитиков процессов.

### Отчёт по просроченным задачам

Руководитель просит показать просроченные задачи за последний квартал по командам и
распределить причины задержек. Сервис применяет доступ пользователя, выбирает нужный
период, группирует задачи и возвращает таблицу, диаграмму и пояснение расчётов.

### Сопоставление задач и выручки

Руководитель клиентского направления запрашивает задачи MWS Track Rails и выручку из
системы управления клиентами за последний месяц. Сервис объединяет данные по клиентам
и показывает, как объём работ соотносится с финансовыми показателями.

### Анализ движения задач по статусам

Руководитель команды просит построить воронку прохождения задач через статусы и показать
среднее время на каждом этапе. Сервис использует историю переходов, строит воронку и
помогает обнаружить этапы, на которых задачи задерживаются дольше всего.

## Предлагаемое решение

Пользовательский запрос проходит несколько последовательных этапов.

1. Встроенный чат или программный интерфейс принимает текст запроса.
2. Сервис авторизации определяет пользователя, организацию, роль и доступные проекты.
3. Большая языковая модель анализирует формулировку, выделяет показатели, фильтры,
   группировки, период и подходящий вид визуализации.
4. Модель формирует запрос на языке SQL либо выбирает и адаптирует готовый шаблон отчёта.
5. Защитный модуль проверяет запрос и разрешает только безопасное чтение данных.
6. Исполнитель запросов добавляет обязательные ограничения организации и прав доступа.
7. Данные извлекаются из аналитического хранилища.
8. Генератор отчётов строит таблицу, график или информационную панель.
9. Пользователь получает результат вместе с описанием показателей, фильтров, источников
   и времени последнего обновления данных.

## Архитектура

Решение состоит из следующих основных частей.

### Пользовательский интерфейс и программный интерфейс

Встроенный чат обеспечивает работу внутри MWS Track Rails. Программный интерфейс
приложений, или API, позволяет получать аналитику из внешних систем и отображать её
в других продуктах.

### Сервис авторизации

Сервис определяет организацию пользователя и проверяет его права. Идентификатор
организации не принимается из произвольного текста запроса, а извлекается из доверенной
сессии. Это исключает возможность запросить данные другой компании простой подменой
параметра.

### Оркестратор аналитических запросов

Оркестратор управляет всей обработкой: вызывает языковую модель, проверяет наличие
готового шаблона, передаёт запрос на проверку, запускает получение данных, использует
кеш и формирует итоговый ответ.

### Шлюз языковых моделей

Шлюз предоставляет единый способ работы с облачными и локальными моделями. Он очищает
передаваемые данные, формирует запрос к модели, ограничивает объём контекста и учитывает
количество использованных токенов.

### Балансировщик нагрузки языковых моделей

Балансировщик выбирает модель или её экземпляр с учётом доступности, текущей очереди,
времени ответа, лимитов и стоимости. При сбое основной модели запрос направляется в
резервную или локальную модель. Это повышает доступность сервиса и защищает отдельную
модель от перегрузки.

### Проверка и выполнение запросов

Защитный модуль разрешает только операции чтения, проверяет используемые таблицы,
поля и функции, запрещает изменение данных и ограничивает сложность запроса. Исполнение
производится отдельной учётной записью базы данных, которая физически не имеет прав
на запись.

### Аналитическое хранилище

Основным источником для отчётов является отдельное хранилище данных, или DWH. В нём
размещаются подготовленные витрины MWS Track Rails и внешних систем. Такой подход
позволяет хранить историю изменений, объединять источники и не нагружать рабочую базу
таск-трекера аналитическими запросами.

### Генератор отчётов

Компонент преобразует результат запроса в таблицу, график или информационную панель.
Он также создаёт выгрузки в форматах CSV и Excel и формирует понятное описание
использованных данных.

### Аудит и наблюдаемость

Для каждого запроса сохраняются пользователь, организация, исходный вопрос,
сформированный SQL-запрос, использованные источники, время выполнения, результат
проверки и стоимость обращения к модели. Эти сведения позволяют расследовать ошибки,
контролировать безопасность и оценивать стоимость эксплуатации.

## Работа с данными

Данные MWS Track Rails и внешних систем поступают в аналитическое хранилище через
коннекторы. Предпочтительный вариант — получать события об изменениях и периодически
сверять состояние через API. Если события недоступны, используется регулярная
инкрементальная загрузка только изменившихся записей.

Для первой версии необходимы следующие витрины:

- задачи и их текущее состояние;
- история переходов между статусами;
- проекты, команды и исполнители;
- спринты и состав спринтов;
- затраченное рабочее время;
- связь задач с клиентами;
- финансовые показатели по клиентам.

История переходов особенно важна для расчёта среднего времени на этапах, воронки,
диаграммы сгорания задач и накопительного потока.

## Безопасность

Языковая модель не является доверенным элементом системы. Она не получает учётные
данные хранилища и не выполняет запрос самостоятельно.

Безопасность обеспечивается несколькими уровнями:

- отдельной ролью базы данных только для чтения;
- обязательной проверкой структуры SQL-запроса;
- перечнем разрешённых таблиц, полей и функций;
- добавлением ограничений организации и прав доступа на стороне сервера;
- ограничением времени выполнения, числа строк и объёма обрабатываемых данных;
- раздельным кешированием и хранением выгрузок для каждой организации;
- аудитом всех пользовательских запросов и действий модели;
- исключением чувствительных текстов и комментариев из запроса к внешней модели;
- возможностью использовать локальную модель в закрытом контуре заказчика.

## Отчёты и пояснение результатов

Сервис поддерживает таблицы, линейные, столбчатые и круговые диаграммы, воронки,
диаграммы сгорания задач, накопительный поток и комбинированные информационные панели.

Доступны фильтрация, группировка, сравнение периодов, накопительные итоги и основные
агрегации: сумма, количество, среднее, минимальное и максимальное значение.

Каждый ответ содержит:

- список источников;
- использованные показатели;
- применённые фильтры и группировки;
- время последнего обновления;
- предупреждения о неполноте данных;
- краткое объяснение полученного результата.

## Производительность и доступность

Типовой отчёт должен формироваться не более чем за 30 секунд. Для этого используются
аналитические витрины, предварительные расчёты, ограничение тяжёлых запросов и кеширование
повторяющихся результатов. Большие выгрузки выполняются в фоновом режиме и не мешают
интерактивным запросам.

Целевая доступность сервиса составляет не менее 99,5 процента. Основные компоненты
не хранят локальное состояние и могут запускаться в нескольких экземплярах. При
недоступности основной языковой модели используется резервная модель или готовые
шаблоны отчётов.

## Масштабирование и управление стоимостью

Сервисы обработки запросов, загрузки данных и формирования отчётов масштабируются
горизонтально. Для каждой организации задаются ограничения на частоту и число
одновременных запросов, размер выгрузки и потребление ресурсов.

Расходы на языковые модели снижаются за счёт кеширования, использования небольшой
модели для простых запросов, передачи только необходимой части схемы данных и вызова
более мощной модели лишь для сложных случаев. Стоимость каждого запроса измеряется
и может ограничиваться на уровне организации.

## Развёртывание

В облачной версии используется общая платформа с логической изоляцией данных компаний.
Для заказчиков с повышенными требованиями возможен выделенный контур.

В локальной версии компоненты разворачиваются в инфраструктуре заказчика. Аналитическое
хранилище и языковая модель могут работать полностью внутри закрытого контура без
передачи данных во внешние сервисы.

## Этапы развития

### Минимально жизнеспособная версия

Первая версия работает только с данными MWS Track Rails. Она поддерживает основные
показатели по задачам, срокам, статусам, исполнителям и спринтам, базовые графики,
CSV-выгрузку, ролевой доступ, изоляцию организаций, проверку SQL и аудит.

### Вторая версия

Подключаются система управления клиентами и учёт рабочего времени, комбинированные
информационные панели, уточняющие вопросы в диалоге, Excel-выгрузка, сохранённые и
плановые отчёты.

### Полнофункциональная версия

Подключаются финансовые и документные системы, расширенный конструктор информационных
панелей, автоматический поиск аномалий, локальная языковая модель, пользовательские
показатели и управление стоимостью по организациям.

## Основные риски

Главные риски проекта связаны с неверной интерпретацией показателей языковой моделью,
утечкой данных между организациями, тяжёлыми запросами, отсутствием полной истории
задач и высокой стоимостью моделей.

Для снижения рисков используются каталог показателей, готовые шаблоны, проверка SQL,
многоуровневая изоляция, ограничения ресурсов, сохранение истории событий, кеширование
и выбор модели по сложности запроса.

## Ожидаемый эффект

Сервис сокращает время подготовки отчёта, снижает зависимость пользователей от
аналитиков и позволяет быстрее принимать решения на основе актуальных данных. Единая
точка доступа к аналитике делает показатели понятнее, а обязательное пояснение каждого
результата повышает доверие к сформированным отчётам.

Таким образом, проект дополняет MWS Track Rails интеллектуальным аналитическим слоем,
который сочетает удобство естественного языка, возможности объединения данных и
контролируемый безопасный доступ к корпоративной информации.
