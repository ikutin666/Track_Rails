# Словарь терминов проекта

## Искусственный интеллект

Технологии, позволяющие программе анализировать информацию, понимать запросы и
формировать результат способом, похожим на интеллектуальную работу человека.

## Большая языковая модель — LLM

Модель, способная понимать и создавать текст. В проекте она определяет намерение
пользователя, показатели, фильтры и параметры запроса. Сокращение LLM происходит от
английского Large Language Model.

## Балансировщик нагрузки языковых моделей

Компонент, распределяющий запросы между несколькими моделями или их экземплярами.
Он учитывает доступность, очередь, скорость ответа, лимиты и стоимость, а при сбое
переключает запрос на резервную модель.

## Естественный язык

Обычная человеческая речь, в отличие от языка программирования или SQL. Например:
«Покажи просроченные задачи за последний квартал».

## Запрос пользователя

Вопрос или команда, которую пользователь отправляет сервису через чат или программный
интерфейс.

## Намерение пользователя

Цель запроса, определённая системой. Например: построить отчёт, сравнить команды,
вычислить среднее время или получить список просроченных задач.

## SQL

Язык запросов к базам данных. Используется для фильтрации, группировки и получения
необходимых данных. В проекте разрешены только безопасные операции чтения.

## Хранилище данных — DWH

Отдельная база для аналитики, в которую собираются данные из MWS Track Rails и внешних
систем. Сокращение DWH происходит от английского Data Warehouse.

## Аналитическая витрина

Подготовленная часть хранилища данных для определённой группы отчётов. Например,
витрина просроченных задач или история переходов задач по статусам.

## Рабочая база данных

Основная база MWS Track Rails, обслуживающая создание и изменение задач. Тяжёлые
аналитические запросы в ней не выполняются, чтобы не замедлять продукт.

## API

Программный интерфейс, через который одна система обращается к другой. В проекте API
позволяет отправлять аналитические запросы и получать результаты без использования чата.

## CRM

Система управления отношениями с клиентами. Может предоставлять сведения о клиентах,
договорах и выручке для объединения с задачами MWS Track Rails.

## Коннектор

Компонент, который получает данные из внешней системы и передаёт их в аналитическое
хранилище.

## ETL

Процесс извлечения данных, их преобразования и загрузки в хранилище. Сокращение
происходит от английских слов Extract, Transform, Load.

## Оркестратор

Компонент, управляющий обработкой запроса: вызывает языковую модель, выбирает шаблон,
запускает проверку, получает данные и передаёт их генератору отчётов.

## Каталог шаблонов запросов

Хранилище заранее проверенных шаблонов SQL и обращений к внешним сервисам. Языковая
модель выбирает нужный шаблон и заполняет только разрешённые параметры.

## Маршрутизатор запросов

Компонент, который определяет способ выполнения: использовать готовый шаблон,
обратиться к внешнему сервису или применить резервную генерацию SQL.

## Защитный модуль — SQL Guard

Компонент, проверяющий сформированный SQL. Он запрещает изменение данных, неизвестные
таблицы и функции, а также ограничивает время и объём выполнения.

## Исполнитель запросов — Query Executor

Компонент, который выполняет проверенный запрос в хранилище данных. Он работает под
учётной записью, имеющей права только на чтение.

## Исполнитель интеграционных запросов

Компонент, вызывающий разрешённые операции внешних сервисов по заранее проверенным
шаблонам.

## Режим только для чтения — read-only

Режим, в котором разрешено получать данные, но запрещено создавать, изменять или
удалять их.

## Ролевое управление доступом — RBAC

Способ управления правами на основе роли пользователя. Например, руководитель видит
данные своего подразделения, а исполнитель — только доступные ему задачи.

## Организация-клиент — tenant

Отдельная компания, использующая облачный сервис. Данные каждой организации должны
обрабатываться независимо от данных остальных клиентов.

## Изоляция организаций — tenant isolation

Набор мер, не позволяющих пользователю одной компании получить данные другой компании.
Ограничения действуют в базе, кеше, отчётах и файлах выгрузки.

## Многопользовательская архитектура — multi-tenant

Архитектура, в которой один экземпляр сервиса обслуживает несколько организаций,
сохраняя строгую изоляцию их данных и настроек.

## Аудит

Запись истории действий: кто отправил запрос, какой шаблон или SQL использовался,
какие источники были запрошены и чем завершилась обработка.

## Мониторинг

Наблюдение за состоянием системы: временем ответа, ошибками, доступностью компонентов
и свежестью данных.

## Учёт стоимости

Подсчёт расходов на работу языковой модели и обработку данных. Позволяет контролировать
стоимость отдельных запросов и устанавливать ограничения для организаций.

## Токен

Небольшая часть текста, обрабатываемая языковой моделью. Количество токенов влияет на
скорость и стоимость обращения к модели.

## Запрос к модели — prompt

Инструкция и данные, передаваемые языковой модели. В проекте в такой запрос включается
только необходимая информация без паролей и необработанных чувствительных данных.

## Кеш

Временное хранилище ранее полученных результатов. Позволяет быстрее отвечать на
повторяющиеся запросы и снижать расходы.

## Визуализация

Графическое представление данных: график, диаграмма, воронка или информационная панель.

## Информационная панель — дашборд

Экран, объединяющий несколько показателей, таблиц и графиков в одном месте.

## Диаграмма сгорания — burn-down

График, показывающий, как со временем уменьшается объём невыполненной работы в спринте.

## Накопительный поток — cumulative flow

Диаграмма, показывающая изменение количества задач в каждом статусе с течением времени.
Помогает находить перегруженные этапы процесса.

## Воронка статусов

Представление количества задач, прошедших через последовательные этапы рабочего процесса.

## Масштабируемость

Способность системы обслуживать больше пользователей и данных без заметного ухудшения
скорости работы.

## Доступность

Доля времени, в течение которого сервис работает и способен отвечать на запросы.
Требование проекта — не менее 99,5 процента.

## SLA

Согласованные показатели качества сервиса, например доступность и максимальное время
формирования типового отчёта.

## Облачное развёртывание

Режим, в котором сервис работает на инфраструктуре поставщика и обслуживает несколько
организаций с изоляцией их данных.

## Локальное развёртывание — on-premise

Режим, в котором сервис устанавливается в инфраструктуре заказчика. Данные и языковая
модель могут полностью оставаться внутри закрытого контура.

## Отказоустойчивость

Способность системы продолжать работу при сбое отдельного компонента, например за счёт
резервной модели, нескольких экземпляров сервисов или готовых шаблонов.

## MVP

Минимально жизнеспособная версия продукта, содержащая только основные функции,
необходимые для проверки ценности решения на реальных пользователях.

## Трейд-офф

Компромисс между преимуществом и недостатком решения. Например, отдельное хранилище
ускоряет аналитику и защищает рабочую базу, но данные обновляются с небольшой задержкой.

## Модель C4

Способ описания архитектуры системы на нескольких уровнях детализации: системный
контекст, контейнеры, компоненты и программный код.

## Системный контекст C4

Верхнеуровневая схема, показывающая пользователей, проектируемую систему и внешние
системы, с которыми она взаимодействует.

## Контейнер C4

Отдельно запускаемое приложение, сервис или хранилище. Контейнер C4 не обязательно
является контейнером Docker.

## Компонент C4

Внутренняя функциональная часть одного контейнера. Например, оркестратор или защитный
модуль внутри аналитического сервиса.
