# Текст защиты проекта

Ориентировочная продолжительность выступления — 6–7 минут.

## Вступление

Добрый день, уважаемые члены жюри.

Я представляю проект ИИ-сервиса аналитики для MWS Track Rails.

MWS Track Rails уже помогает создавать проекты и задачи, назначать исполнителей,
планировать спринты, работать с файлами, обсуждать задачи в комментариях и использовать
ИИ-агентов. При этом продукт хранит большое количество данных о статусах, сроках и
работе команд. Но наличие данных ещё не означает, что пользователь может быстро получить
из них аналитический ответ. Для подготовки нестандартного отчёта часто требуется помощь
аналитика, выгрузка таблиц или ручное объединение информации из нескольких систем.

Наш проект решает эту проблему. Пользователь задаёт вопрос обычным языком и получает
готовый отчёт, таблицу, график или информационную панель с объяснением результата.

## Проблема и ценность

Представим руководителя проекта, которому нужно понять, какие команды чаще нарушали
сроки в последнем квартале и по каким причинам. Сегодня такой запрос может потребовать
нескольких выгрузок, ручной обработки и ожидания ответа аналитика.

В нашем решении руководитель пишет: «Покажи просроченные задачи за последний квартал
по командам и построй диаграмму причин задержек».

Сервис сам определяет период, нужные показатели, группировку и вид диаграммы. При этом
он учитывает права пользователя и показывает только доступные проекты. В результате
руководитель получает ответ за минуты или секунды, а не за часы или дни.

Ещё один важный сценарий — объединение источников. Например, можно сопоставить задачи
MWS Track Rails с выручкой из системы управления клиентами и получить сводный отчёт
по клиентам. Это позволяет увидеть не просто объём выполненной работы, а его связь
с бизнес-результатом.

Третий сценарий — анализ движения задач через статусы. Сервис строит воронку и
показывает среднее время на каждом этапе, помогая найти узкие места процесса.

## Как работает решение

Пользователь обращается к сервису через встроенный чат MWS Track Rails или через
программный интерфейс.

Сначала система проверяет пользователя, его организацию, роль и доступные проекты.
Затем большая языковая модель анализирует вопрос: определяет сущности, период,
показатели, фильтры, группировки и формат результата.

Для типовых запросов сервис может использовать готовый шаблон отчёта. Для более
свободных формулировок модель создаёт SQL-запрос по разрешённой схеме данных.

После этого запрос обязательно проходит защитную проверку. Разрешено только чтение
данных. Нельзя изменить или удалить информацию, обратиться к неизвестной таблице или
запустить чрезмерно тяжёлый запрос. Ограничения организации и прав пользователя
добавляет сервер, а не языковая модель.

Проверенный запрос выполняется в аналитическом хранилище. Полученные данные передаются
генератору отчётов, который строит таблицу, график или информационную панель.

Вместе с результатом пользователь видит, какие показатели и фильтры использовались,
из каких источников получены данные, когда они обновлялись и есть ли ограничения
по полноте.

## Архитектура и данные

Основой решения является отдельное аналитическое хранилище данных. Мы сознательно
не выполняем тяжёлые аналитические запросы в рабочей базе MWS Track Rails.

Такой подход даёт три преимущества.

Первое — аналитика не влияет на скорость основного продукта.

Второе — мы можем хранить историю переходов задач между статусами. Без этой истории
невозможно корректно считать среднее время на этапах, строить диаграммы сгорания и
накопительного потока.

Третье — в одном месте можно объединить данные MWS Track Rails, системы управления
клиентами, учёта времени и финансовых систем.

Данные поступают через коннекторы и обновляются инкрементально. Для первой версии
достаточно задержки в несколько минут. Если конкретному клиенту нужна более оперативная
аналитика, можно использовать поток событий или отдельную реплику для чтения.

## Безопасность

Главный принцип безопасности состоит в том, что языковая модель не является доверенным
контуром. Она не получает пароль от базы данных и не исполняет запрос самостоятельно.

Исполнитель работает под отдельной ролью только для чтения. Каждый SQL-запрос
проверяется. Данные разных организаций изолированы. Права доступа применяются на стороне
сервера. Кеш и выгрузки также разделяются по организациям.

Все запросы попадают в аудит: мы знаем, кто задал вопрос, какой запрос был сформирован,
какие источники использовались, сколько времени заняла обработка и сколько стоило
обращение к модели.

Для локального развёртывания можно использовать языковую модель внутри инфраструктуры
заказчика. В этом режиме корпоративные данные вообще не покидают закрытый контур.

## Производительность и стоимость

По техническому заданию типовой отчёт должен формироваться не более чем за 30 секунд.
Для достижения этого показателя мы используем подготовленные витрины, предварительные
агрегации и кеширование. Тяжёлые выгрузки выполняются в фоновом режиме и не замедляют
обычные запросы.

Целевая доступность составляет 99,5 процента. Основные сервисы могут запускаться в
нескольких экземплярах, а при недоступности основной модели можно использовать
резервную модель или готовый шаблон.

Стоимость контролируется несколькими способами. Простые запросы обрабатывает небольшая
модель. Более мощная модель вызывается только для сложных случаев. Повторяющиеся
результаты кешируются, а в запрос модели передаётся только необходимая часть описания
данных. Для каждой организации можно установить лимиты.

## Этапы развития

В минимально жизнеспособную версию входят данные MWS Track Rails, базовые показатели
по задачам и спринтам, основные графики, CSV-выгрузка, проверка SQL, ролевой доступ,
изоляция организаций и аудит.

На втором этапе подключаются система управления клиентами и учёт времени, появляются
комбинированные панели, уточняющие вопросы, Excel-выгрузка и сохранённые отчёты.

Полнофункциональная версия включает финансовые и документные системы, автоматический
поиск аномалий, пользовательские показатели, расширенный конструктор панелей и локальную
языковую модель для закрытых контуров.

## Завершение

Итак, наш проект решает понятную прикладную задачу: превращает данные MWS Track Rails
в доступные ответы для руководителей, команд и аналитиков.

Ключевая особенность решения — сочетание удобства естественного языка с контролируемой
архитектурой. Языковая модель помогает понять вопрос и сформировать запрос, но права
доступа, безопасность и исполнение остаются под управлением обычных программных
компонентов.

В результате пользователь быстрее получает аналитику, аналитики тратят меньше времени
на повторяющиеся выгрузки, а компания принимает решения на основе более актуальных
и прозрачных данных.
